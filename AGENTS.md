# Emerald March development requirements

This is an independently maintained project. Any modification to this project or its deployment requires explicit user approval for the affected project and the specific change. A general request to maintain or synchronize the portfolio, Play hub or Learn hub does not authorize changes here, including links, content, layout, behavior, themes, documentation or hosting. Approval already given for a specific change remains valid; do not ask again for that same work. The requirements below guide authorized work and do not grant permission to make additional changes.

- Keep the game self-contained in `index.html` with its embedded engine and game scripts. Preserve the Three.js license notice, offline runtime, existing gameplay systems, and compatible local saves.
- Preserve both desktop mouse/keyboard controls and the compact touch interface. Mobile play must keep the battlefield visible, expose every action through readable paginated commands, and support selecting units/groups, giving orders, building, panning, and zooming. Visible compact Select/Order/Group controls must work with touch, mouse, and pen input; retain the full desktop left/right-click behavior when the compact interface is hidden. Open one mobile panel at a time; respect safe areas and the dynamic viewport.
- Fullscreen requests belong in explicit Start/Resume or fullscreen-button gestures. Never request fullscreen merely on page load. Preserve the fullscreen toggle, the player's deliberate exit preference, and the playable fallback when an API is unavailable or rejected.
- Keep creator navigation in menus, outside the active battlefield. Use one `data-creator-links` group with Website `https://aadityamore.com/`, GitHub `https://github.com/aaditya-v-more`, and LinkedIn `https://www.linkedin.com/in/aadityavmore/`. Preserve the `.modal-actions` collection-return integration hook.
- Run `npm test` and `npm run build` after relevant changes. Add regression checks for changes to touch input, fullscreen, panel state, or save behavior; DOM tests do not replace real browser visual and touch-device checks.
- Do not deploy or change hosting settings without task authorization. A push to main may trigger the repository's existing Vercel integration.

- Keep this game’s original palette. Synchronization refers only to creator/source navigation links, and adding or updating those links across projects requires explicit user permission. It does not authorize adding themes, using device appearance, or synchronizing appearance across sites. Preserve the existing authorized creator links.

- The Vercel project `age-of-empires-v` publishes successful `main` pushes using `vercel.json`. The Play route forwards to that deployment; keep `https://play.aadityamore.com/emerald-march/` as the canonical and preserve the absolute Back to Play menu link. Verify the exact pushed commit reaches production instead of manually redeploying it.
